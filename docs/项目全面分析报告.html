项目优势与不足

核心优势

  • 架构清晰：前后端分离，13 个业务模块职责明确，分层规范（Controller/Service/Mapper/Entity）
  • 企业级特性：多租户 SaaS、RAG 智能检索、开放 API/Webhook、i18n 双语、结构化日志、Prometheus 监控
  • 信创就绪：支持达梦/人大金仓数据库，ARM64 架构，完整私有化部署方案
  • 测试保障：189 个测试用例全绿，Service 层全覆盖，测试代码占比 31.7%
  • 安全完善：Spring Security + JWT，多租户行级隔离，API Key 认证，Webhook HMAC 签名，审计日志
  • AI 集成：支持 OpenAI/通义/豆包多模型，模拟模式便于无 API Key 开发，RAG 检索增强生成
  • 文档齐全：12 份技术文档，涵盖架构、部署、信创适配、路线图、开发指南等
  • 配置灵活：4 套环境 Profile（dev/local/prod + 默认），配置全外部化，.env 模板即用

待改进项

  • 前端页面较少：仅 11 个页面，部分后端模块（asset/statistics）前端页面较简单，开放 API 管理界面缺失
  • 无 CI/CD：.github 目录为空，缺少 GitHub Actions 自动化构建、测试、部署流水线
  • 向量存储简单：RAG 向量以 JSON 存储在 MySQL TEXT 列，未使用专业向量数据库（Milvus/Qdrant/PgVector），大数据量下性能受限
  • geo-engine 独立：Node.js 数据采集引擎与后端分离，集成度较低，缺少统一调度
  • 无缓存策略：Redis 主要用于会话和 Token，业务数据缺少缓存层设计，高并发下数据库压力大
  • 接口文档：缺少 Swagger/OpenAPI 自动生成的 API 文档，APIDOC.md 为手写
  • 前端类型安全：未使用 TypeScript，大型项目维护性受限
  • 无限流降级：缺少 Sentinel/Hystrix 等限流熔断组件，AI 调用无降级策略
  • 数据库迁移：使用手动 SQL 脚本（V2/V3/V4），未集成 Flyway/Liquibase 自动化版本管理
